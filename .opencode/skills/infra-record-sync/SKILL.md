# infra-record-sync

절차와 기록 규칙의 원본은 [사내 인프라 정보](../../../deploy/shared/docs/infrastructure/README.md)의 `기록 규칙`과 `대기 작업을 서버 조회로 확인하는 방법`이다.

## 진행 방법
1. [서버 적용 대기 작업](../../../deploy/shared/docs/infrastructure/pending.md)을 읽고 행마다 원본 절의 표에서 확인 방법을 고른다. 범위를 지정받았으면 그 분류만 본다.
2. [조회] 명령을 실행한다. 관리 호스트의 명령으로 확인할 수 없는 항목은 [접근 경로](../../../deploy/shared/docs/infrastructure/access.md)의 해당 절에 적힌 `찾는 방법`으로 확인하고, 처음 확인한 접근 방법은 그 표에 기록한다. 접근이 막히면 시도한 명령과 필요한 것을 pending 행에 적는다.
3. 확인된 행은 원본 문서의 현재 값을 `서버 조회` 상태로 고치고 pending 행을 삭제한다. 목표와 다르면 pending 행의 `현재 상태`만 관측값으로 고친다.
4. 새로 발견한 서버·주소·사내 host는 해당 원본과 [별칭 표](../../../deploy/shared/docs/infrastructure/aliases.json)에 함께 추가한다.

## 지킬 것
- 수정할 수 있는 파일은 `deploy/shared/docs/infrastructure/` 아래뿐이다.
- 조회하지 않은 항목의 상태를 바꾸지 않는다. 날짜·완료 기록·비밀값을 쓰지 않는다.
- 값이 충돌하면 하나를 고르지 않고 후보 값과 남은 확인을 적는다.

## 보고 형식
- 확인해 정리한 행(원본 문서와 바꾼 값), 관측값이 목표와 달라 남긴 행, 조회로 확인할 수 없어 남긴 행
- 실행한 조회 명령과 결과 요약, 수정한 파일
- 별칭 표에 추가한 항목(별칭 이름만)
