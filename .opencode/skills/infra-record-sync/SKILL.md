# infra-record-sync

조회 기준은 [사내 인프라 정보](../../../deploy/shared/docs/infrastructure/README.md)의 `대기 작업을 서버 조회로 확인하는 방법`이다. 일상 진행 결과는 [운영 기록](../../../deploy/shared/docs/operations/01-checkout.md#운영-기록)을 권장한다.

## 진행 방법
1. [서버 적용 대기 작업](../../../deploy/shared/docs/infrastructure/pending.md)과 운영 계정의 `state.md`를 읽고 해당 범위의 확인 항목을 고른다.
2. [조회] 명령을 실행한다. 접근 방법이 필요한 항목은 [접근 경로](../../../deploy/shared/docs/infrastructure/access.md)의 해당 절을 따른다. 확인한 방법이나 막힌 이유를 운영 기록에 적는다.
3. 운영 기록을 사용하는 경우 `state.md`에 관측값·완료 여부·남은 일을 정리하고 `progress.md`에 진행 내역을 추가한다.
4. 새 서버·주소·별칭 등 공유할 변경은 조회 근거가 있으면 인프라 원본의 기록 규칙에 따라 반영할 수 있다.

## 지킬 것
- 일상 작업 기록은 `~/.local/state/tailwind/ops/`를 권장한다. 인프라 원본을 갱신했다면 수정 경로와 조회 근거를 보고한다.
- 조회하지 않은 항목을 완료로 표시하지 않는다. 운영 기록과 보고에서 비밀값은 제외한다.
- 값이 충돌하면 하나를 고르지 않고 후보 값과 남은 확인을 적는다.

## 보고 형식
- 확인한 항목과 원본의 차이, 남은 작업 및 필요한 Git 원본 변경 제안
- 실행한 조회 명령과 결과 요약, 수정한 파일
- 추가를 제안한 별칭 이름
