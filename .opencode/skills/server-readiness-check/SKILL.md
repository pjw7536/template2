# server-readiness-check

절차의 원본은 [배포 가이드의 설치 준비 점검](../../../deploy/README.md#설치-준비-점검)과 각 앱 가이드(`deploy/<app>/README.md`)의 `한눈에 보기`·`사전 준비`다.

## 진행 방법
1. 대상 앱을 정한다. 지정이 없으면 배포 가이드의 설치 순서대로 모든 앱이다.
2. 앱마다 `make ops-preflight APP=<app> KUBE_CONTEXT="<context>"`를 실행하고, 앱 가이드 `사전 준비` 표에서 준비 검사가 다루지 않는 행을 `완료 확인` 칸의 방법으로 확인한다. 다른 노드와 외부 시스템은 [접근 경로](../../../deploy/shared/docs/infrastructure/access.md)의 `찾는 방법`으로 조회한다.
3. 결과를 원본 절의 표 형식으로 앱별로 정리하고 배포 가능 여부와 막힌 단계를 보고한다.
4. 남은 서버 작업을 `deploy/shared/docs/infrastructure/pending.md`에 반영한다.

## 지킬 것
- 조회로 확인한 항목만 `완료`로 기록한다. 준비 검사의 `[자동 준비]`는 배포할 때 실행되므로 `미완료`로 적고 그 명령을 다음 조치에 적는다. 막힌 항목은 시도한 명령과 접근 경로 절의 `막히면 요청할 것`을 적는다.
- 준비가 끝난 앱이 있어도 이 스킬에서는 배포하지 않는다. 사용자가 배포까지 요청했으면 `server-deploy-routine`으로 이어서 진행한다.

## 보고 형식
- 앱별 표: 항목 | 상태(완료/미완료/확인 필요) | 근거 | 다음 조치
- 앱별 배포 가능 여부와 막힌 항목
- 수정한 운영 기록 파일
