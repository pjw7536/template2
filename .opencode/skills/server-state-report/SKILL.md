# server-state-report

절차의 원본은 [서버 상태 보고](../../../deploy/shared/docs/operations/04-drift.md#서버-상태-보고)다. 사내망 밖의 개발 환경은 서버를 볼 수 없으므로, 사용자가 옮길 수 있게 사내 주소 정보가 없는 보고서를 만든다.

## 진행 방법
1. 조회만 한다. 배포·수정이 필요하면 보고서에 적고 `server-deploy-routine`으로 따로 진행한다.
2. 원본 절차의 순서대로 보고서를 만든다. 미등록 값에 붙은 임시 별칭은 [checkout 밖 운영 기록](../../../deploy/shared/docs/operations/01-checkout.md#운영-기록)에 적고, 공동 별칭이 필요할 때 등록을 제안한다.
3. 사용자가 외부에서 받은 질문(별칭으로 적힘)을 전달하면 별칭 표로 실제 대상을 찾아 조회하고, 결과를 `make -s ops-redact`로 바꿔 보고서 끝에 붙인다.

## 지킬 것
- 외부로 전달하는 텍스트는 `make ops-report` 또는 `make ops-redact`의 표준 출력뿐이다. kubectl 출력, 운영 기록, 별칭 표 자체를 그대로 전달하지 않는다.
- 표준 오류에 나오는 `별칭 미등록 값` 목록은 실제 값이므로 전달하지 않는다.
- 비밀번호·토큰·개인키 값은 어떤 경우에도 보고서에 넣지 않는다.

## 보고 형식
- 보고서 파일 경로, 대상 앱, 주소·서버명이 남지 않았는지 검사한 결과
- 추가를 제안한 별칭 이름과 운영 기록 경로
- 생성하지 못한 절과 이유
