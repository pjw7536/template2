# ExecPlan: Markdown 가독성과 문서 탐색 체계 정리

## 목표
- 저장소의 모든 Markdown을 검토하고 사용자가 목적에 맞는 문서를 쉽게 찾고 이해하도록 개선한다.
- 명확한 문서는 유지하고, 필요한 설명·연결·배치만 수정한다.

## 현재 상태
- 루트와 앱, 배포, 개발 환경, 기술 문서, 에이전트 지침·과거 계획에 Markdown이 분산되어 있다.
- 이전 문서 정합성 작업과 배포 코드의 staged·unstaged 변경이 이미 존재하므로 현재 작업 사본을 기준으로 보존한다.
- 기존 감사 계획은 완료 기록이므로 이번 가독성·구성 검토를 별도 계획으로 관리한다.

## 범위
- 저장소가 소유한 `.md`·`.markdown` 문서와 숨김 도구 문서.
- 의존성·생성물은 제외한다. 실행 코드·환경 설정·API·DB·권한 계약은 변경하지 않는다.

## 설계
- `apps/<app>`, `deploy/<app>`, `local/<app>`의 기존 소유권을 유지한다.
- 현재 안내와 과거 작업 기록을 구분하고 진입 문서에서 목적별로 연결한다.
- 문서 이동은 소유 위치가 잘못되었거나 탐색을 명확히 개선할 때만 하고 참조를 함께 갱신한다.
- 명령·경로·조건을 보존하며 긴 문장, 중복 설명, 불친절한 용어를 필요한 만큼 다듬는다.
- 영역을 나누어 전체 문서를 검토하고, 영역별 검토·유지·변경 근거를 남긴다.

- `make audit-tools-test`
- 전체 Markdown 상대 파일 링크와 문서 anchor 검사
- 작업 전 사본 대비 변경 파일·내용 점검
- `git diff --check`

## 위험과 대응
- 기존 변경과 섞이지 않도록 작업 전 Markdown 사본과 비교한다. stage·commit·push하지 않는다.
- 과거 계획의 경로·명령은 당시 기록으로 보존하며 현재 사용법으로 오인하지 않도록 안내한다.
- 실제 서버·서비스를 호출하거나 문서의 운영 명령을 실행하지 않는다.

## 설명 모순의 수정 근거

- Data Movement 요약: `apps/portal/api/api/data_movement/views.py`의 `summary.all_failed`와 `ct_process_comment/services/summary.py`를 대조해 일부 실패와 전체 실패의 HTTP 응답 설명을 구분했다.
- Observer 후보: `web/src/features/observer/api/lineSdwtOptions.js`와 `api/api/drone/selectors/targets.py`를 대조해 제거된 Account 후보 설명을 현재 Drone·station 조회 기준으로 수정했다. 두 경로는 `apps/portal` 기준이다.
- API 로컬 주소는 통합 진입점 안내, 프론트엔드 높이 소유는 Web 지침과 맞췄다. 실행 코드·계약은 변경하지 않았다.
