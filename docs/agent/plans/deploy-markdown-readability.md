# ExecPlan: 배포 문서 가독성 개선

## 목표
- deploy의 사람이 읽는 Markdown 안내를 쉽게 따라갈 수 있는 문장과 문단으로 정리한다.
- 명령·설정값·기술적 의미·문서 경로와 기존 제목을 유지한다.

## 현재 상태
- deploy에 Markdown 60개가 있으며 AGENTS.md는 작업 규칙 문서다.
- 안내 문서에는 긴 병렬 문장, 한 문단에 섞인 준비·실행·확인 설명, 영어 용어와 과도한 강조가 남아 있다.
- 작업 전 문서 사본을 임시 경로에 보존했다. 기존 사용자·이전 작업 변경을 유지한다.

## 범위
- deploy의 안내 문서 59개를 검토하고 필요한 본문 표현·배치·서식을 다듬는다.
- 작업 규칙인 AGENTS.md, 코드·manifest·env·실제 서버 설정은 변경하지 않는다.

## 설계
- 문서 앞부분에 대상·실행 위치·먼저 읽을 내용을 짧게 설명한다.
- 한 문단은 하나의 목적만 다루고, 순서가 있는 작업과 병렬 확인 항목을 구분한다.
- 비교·경로 대응 표는 유지하고, 긴 표 셀이나 나열식 문장은 짧은 설명으로 정리한다.
- env가 설정 원본이며 Kubernetes Secret은 전달 리소스라는 기존 계약을 명확하게 설명한다.
- 명령 코드 블록과 기존 제목을 보존해 실행 의미와 링크 대상을 유지한다.
- 과거 기록은 기록 시점과 현재 확인이 필요한 부분을 분명하게 구분한다.

## 실행 단계
- [x] 공통 진입점·환경설정·Kubernetes 안내 정리
- [x] 앱별 설치·설정·운영 안내 정리
- [x] 인증서·Ingress·인프라·운영 참고 정리
- [x] 명령·제목·링크 보존과 문서 검사

## 검증
- 작업 전 사본과 비교해 코드 블록·기존 제목 보존 여부를 확인한다.
- deploy 문서의 상대 링크와 제목 anchor를 확인한다.
- `make audit-docs`, `git diff --check`.
- Markdown 밖의 실행 코드·설정이 이번 작업으로 바뀌지 않았는지 확인한다.

## 위험과 대응
- 줄이면서 조건이나 주의점이 사라지지 않도록 기존 문장과 대조한다.
- 날짜가 있는 과거 기록을 현재 서버 상태로 바꾸지 않는다.
- 명령을 새로 만들거나 서버 설정을 추측하지 않는다.
