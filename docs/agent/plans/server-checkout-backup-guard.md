# ExecPlan: 서버 선택 전환 시 백업 파일 보존

## 목표
- 앱 선택을 바꿀 때 Git에서 제외된 설정·백업 파일이 삭제되지 않게 한다.
- 제거될 경로에 파일이 있으면 선택 범위와 파일을 변경하지 않고 중단한다.

## 현재 상태
- 백업 보호와 정상 전환을 검증하는 checkout 테스트 23개가 통과했다.
- 사용자 피드백에 따라 별도 Python 검사기를 제거하고 기존 셸 스크립트 안으로 검사를 줄인다.
- root 파일·선택 디렉터리·cone 모드의 상위 디렉터리 파일은 계속 허용한다.
- 현재 작업 공간의 기존 미커밋 변경과 실제 백업은 보존한다.

## 범위
- deploy/shared의 선택 전환 도구. 별도 검사 helper는 제거한다.
- apps/tooling의 서버 checkout 회귀 테스트와 deploy/SERVER_CHECKOUT.md.
- 실제 작업 공간의 sparse 범위 변경, 백업 이동·삭제, 클러스터 적용은 수행하지 않는다.

## 설계
- 기존 수정·미추적 파일 검사를 유지한다.
- git ls-files의 NUL 구분 출력으로 ignored 파일을 조회하고 새 cone 선택의 보존 범위와 비교한다.
- 기존 Bash에서 경로만 비교하며 파일 내용은 읽지 않는다. Git 조회 실패는 즉시 중단하고 임시 경로 목록은 종료 시 정리한다.
- 제외될 파일이 있으면 경로를 표시하고 sparse-checkout 실행 전에 실패한다. 자동 이동·삭제·강제 실행 옵션은 추가하지 않는다.
- root 파일과 선택 디렉터리의 상위 경로에 직접 있는 파일은 cone 규칙에 맞춰 허용한다.

## 위험과 대응
- cache·빌드 결과도 ignored 파일로 보호한다. 필요한 이동·정리는 운영자가 직접 결정하며 도구가 임의로 삭제하지 않는다.
- NUL 구분과 경로 표시의 escaping으로 공백·줄바꿈이 있는 파일도 보존한다.
- 검사가 실패하면 기존 sparse 선택과 파일 내용이 그대로인지 확인한다.
