# Python 주석과 docstring

## 적용 범위

사용자가 설명을 요청했거나, 변경한 로직의 정책·전제·부작용을 코드만으로 알기 어려울 때 적용한다.
공개 service·selector의 타입 힌트와 한국어 docstring 요건은 `apps/portal/api/AGENTS.md`를 따른다.
단순 import·명칭·문구 수정으로 주변 파일 전체의 주석을 늘리지 않는다.

## 작성 기준

- 주석·docstring은 한국어로 쓴다. 고유명사와 외부 규격 이름은 원문을 유지한다.
- 함수 이름과 타입으로 드러나지 않는 목적·입출력 제약·부작용·예외만 설명한다. 짧은 공개 함수는 한 줄 docstring으로 충분할 수 있다.
- 업무 정책, 권한 판단 근거, 중복 방지, 시간대 변환, 트랜잭션 경계처럼 비자명한 이유를 해당 코드 가까이에 설명한다.
- View의 request/query 예시는 계약이 복잡하거나 사용자가 요구할 때만 넣는다. 실제 serializer·API 계약과 일치시킨다.
- 모듈 설명·단계 구분은 복잡한 흐름을 이해하는 데 필요할 때만 추가한다. 주석 간격이나 줄 수 비율을 고정하지 않는다.
- `services/__init__.py` 등 공개 facade는 명시적 re-export를 유지한다. 설명을 위해 실행 로직이나 불필요한 예시를 넣지 않는다.

## 확인

- 코드의 동작·불변조건과 설명이 일치하는가?
- 코드가 이미 표현한 내용을 반복하거나 변경 이력·에이전트 메타 설명을 넣지 않았는가?
- 주석 수정만 요청받았다면 실행 코드·공개 API가 유지되는가?

결과 보고는 `safe-file-edit-output` 기준으로 변경 부분과 검증만 간결하게 설명한다.
