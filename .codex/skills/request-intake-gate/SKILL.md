# 요청 분류

## 적용

구현·파일 수정 전에 적용한다. 단순 설명·조회에는 구현용 질문 양식을 강제하지 않는다.
우선순위와 탐색 범위는 루트·대상 영역의 `AGENTS.md`를 따른다.

## 판단 순서

1. 원하는 결과·대상 영역·변경 범위를 짧게 요약한다. 사용자의 언어로 한 번만 설명하고 고정된 영문 요약을 반복하지 않는다.
2. 사용자 지시·기존 계약·대상 코드를 확인해 미확정 사항을 줄인다. 이미 정한 선택이나 승인한 작업은 다시 묻지 않는다.
3. 남은 항목을 아래 기준으로 나누고 필요한 기본값만 알린다.

| 분류 | 기준 | 행동 |
| --- | --- | --- |
| Hard-Block | API·DB·권한·업무 규칙·공개 facade·의존 방향의 정확성을 결정할 정보가 없음 | 해당 변경 전에 번호로 질문하고 답을 기다린다. |
| Soft | 문구·아이콘·간격 등 되돌릴 수 있고 계약을 바꾸지 않는 선택 | 기존 패턴이나 합리적 기본값으로 진행한다. |

Hard-Block 여부는 영역 이름만으로 판단하지 않는다. 계약이 이미 명확한 API 변경이나 기존 경로의 작은 수정에는 추가 질문이 필요하지 않다.

## 질문과 진행

- 한 질문에는 한 결정을 담고 `1.`, `2.`처럼 번호를 붙인다. 선택 기준이나 권장안을 짧게 덧붙인다.
- 예: `1. 목록 응답에 전체 건수가 필요한가요? (후보: 전체 건수 포함 / 다음 페이지 여부만 제공)`
- 답변이 필요한 구현은 보류하고, 답에 의존하지 않는 조사·검증·승인된 작업은 계속한다.
- Soft 항목만 있으면 질문 없이 구현한다. 사소한 가정을 별도 목록으로 길게 나열하지 않는다.
- 범위가 바뀌면 해당 부분만 다시 판단한다. 질문 양식을 채우기 위해 작업을 멈추지 않는다.
