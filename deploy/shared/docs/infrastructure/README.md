# 사내 서버 환경·구성 관리

[공통 배포 문서](../README.md) · [배포 문서 홈](../../../README.md) · [Kubernetes 셋업](../kubernetes/README.md)

사내 서버 환경·노드·VIP·앱 배치와 패키지 미러를 관리하는 공통 진입점입니다.
에이전트는 모든 작업을 시작할 때 이 요약을 읽고, 서버 환경과 관련된 작업에서는 아래 상세 원본을 확인합니다.
이 폴더는 모든 서버 선택 checkout에 포함되므로 루트 `docs/` 없이도 읽을 수 있습니다.

## 작업 전에 알아둘 기준

- 사내 서버 배포는 Kubernetes를 사용합니다. CP1은 관리 명령 실행 위치이며 앱의 실행 노드는 배포 입력으로 별도 결정합니다.
- 사내 의존성은 승인된 미러 또는 반입 파일을 사용합니다. 외부 PC 개발은 public source와 mock을 사용하며 사내망 접속을 전제하지 않습니다.
- 확인된 서버 기준, 저장소의 배포 선언, 절차의 예시는 서로 다릅니다. 기록된 값으로 실제 서버 상태를 대신 판단하지 않습니다.
- 실행 설정의 원본은 앱별 manifest·env·Helm values입니다. 이곳에서는 환경 현황과 근거를 관리하며 비밀번호·토큰·개인키·kubeconfig 내용을 복제하지 않습니다.

## 확인 상태를 기록하는 방법

| 상태 | 의미 | 갱신 기준 |
| --- | --- | --- |
| 사용자 확인·서버 조회 | 서버 출력 또는 명시적인 사용자 확인을 근거로 한 값 | 확인일·대상·근거를 함께 기록. 과거 Ready를 현재 상태로 단정하지 않음 |
| 저장소 선언 | manifest·env·Helm values에서 읽은 배포 입력 | 원본 경로·저장소 대조일을 기록. placeholder는 미확정으로 표시 |
| 문서 기록·예시 | 기존 운영 문서에 적힌 주소·설치 또는 확장 예시 | 출처를 남기고 실제 서버 반영 여부는 별도 확인 |
| 미확인 | 근거가 없거나 대상별로 확인하지 않은 값 | 필요한 조회·확인 주체를 적고 값은 추정하지 않음 |

## 변경할 때 함께 갱신하기

1. 환경·노드·VIP·DNS·앱 배치·스토리지를 변경하거나 새 확인값을 받으면 `cluster.md`의 해당 현재 값을 갱신합니다. 값·확인 상태·확인일·근거·담당자·미해결 항목을 함께 적으며, 담당자를 모르면 `미확인`으로 둡니다.
2. 미러가 추가·변경되면 `01-proxy-mirrors.md`의 매핑·적용 사례와 관련 앱의 입력·설치 절차를 대조합니다. 운영 접속 성공은 실제 확인했을 때만 기록합니다.
3. 설정값은 소유 앱의 원본에서 변경합니다. 이곳에는 필요한 환경 요약과 원본 링크를 남기고 같은 전체 표를 다른 문서에 복제하지 않습니다.
4. 파일 검사·렌더 성공과 실제 클러스터 적용·접속 성공을 구분해 보고합니다. 확인하지 못한 값과 남은 확인 사항은 현황에 유지하고 완료된 작업 이력을 누적하지 않습니다.
