# 사내 인프라 정보 관리 지침

## 원본과 읽기 순서
- 이 폴더는 사용자가 제공하거나 서버에서 확인한 사내 운영 정보의 원본이다. README.md의 분류표와 기록 규칙을 먼저 읽고 대상 주제의 문서만 추가로 확인한다.
- 서버·OS·버전·접속은 servers.md, VIP·DNS·네트워크는 network.md, 서비스·앱 배치·업무 API는 services.md, 저장소·전체 미러 매핑은 repositories.md, 파일·백업 위치·담당자는 operations.md가 소유한다.
- 실행 설정의 원본은 소유 앱의 manifest·env·Helm values다. 정보 기록 요청은 실제 서버 적용 요청으로 확대하지 않는다.

## 변경을 반영할 때
- 항목의 현재 값·용도·확인 상태·설정 원본 또는 확인 근거·담당자·남은 확인을 갱신한다. 새 항목에는 README.md의 입력 양식을 사용한다.
- 확인 날짜·변경 경위·완료 기록·이전 값은 본문에 누적하지 않고 Git 이력으로 추적한다. 현재 유효한 노드명·IP·VIP backend 대응·용도와 전체 미러 목록은 유지하고, 운영 상태가 불확실하면 재확인할 대상을 명시한다.
- 새 정보가 예정·미적용이면 현재 운영 상태와 구분한다. 충돌이 해결되지 않으면 후보 값과 설정 원본 또는 확인 근거·남은 확인을 해당 항목에 표시하고 추정으로 해결하지 않는다.
- 주소·배치·데이터 위치를 바꾸면 README.md의 연관 정보 열에 따라 다른 원본과 소유 앱 설정도 대조한다. 다른 문서에 같은 전체 표를 복제하지 않는다.
- 비밀값 대신 보관 위치·Secret 이름·권한 신청 절차를 기록한다. 저장소 선언과 실제 서버 조회·운영 적용 상태를 구분한다.
- 현재 필요한 이전·복구·호환 절차와 버전·인증서 만료일은 유지한다. 완료된 변경 일지·작업 이력·계획은 누적하지 않는다.

## 검증과 보고
- 문서만 바꾸면 변경 파일의 링크·앵커와 git diff --check를 확인하고 make audit-docs를 실행한다.
- 문서 이동·공통 경로 변경은 node --test apps/tooling/tests/server-checkout.test.cjs도 실행한다. 기존 주소·서버/IP 대응·전체 미러 목록의 보존을 원본과 대조한다.
- 변경 경로·갱신한 정보·검증 결과·실제 서버 조회 여부·남은 확인을 보고한다. 사용자 요청 없이 commit·push하지 않는다.
